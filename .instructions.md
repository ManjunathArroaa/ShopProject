# Master Prompt - Vaishnavi Silks Payment Reminder System

## Project Overview

**Name:** Vaishnavi Silks Kanapuraka - Payment Reminder System  
**Version:** 1.0  
**Purpose:** MSME payment tracking and automated WhatsApp reminder system for monthly customer payment schemes  
**Business Domain:** Saree shop running monthly installment payment schemes (6-12 months)  
**Target Users:** Shop owner and staff (1-3 users), managing 100+ customers  

## Critical Rules - DO NOT BREAK

1. **NEVER modify database schema without migration strategy** - Existing data must be preserved
2. **NEVER change authentication logic without testing** - JWT tokens must remain compatible
3. **NEVER remove or rename API endpoints** - Frontend depends on existing routes
4. **NEVER change SQLAlchemy model relationships** - Cascade delete relationships are critical
5. **Allow duplicate phone numbers** - Multiple family members can share phones
6. **Maintain mobile-first UI** - All changes must work on smartphones
7. **Preserve soft delete pattern** - Customers use `is_active` flag, never hard delete
8. **Keep Twilio optional** - System must work without WhatsApp integration

### Development Environment

- **Database File:** `payment_reminder.db` (SQLite file in project root)

## Database Models

### 1. User (Authentication)
```python
- id: Integer, Primary Key
- username: String, Unique, Indexed
- email: String, Unique, Indexed
- hashed_password: String (bcrypt)
- shop_name: String (optional)
- is_active: Boolean (default True)
- created_at: DateTime (UTC)
- updated_at: DateTime (UTC, auto-update)
```

### 2. Customer (Payment Scheme Members)
```python
- id: Integer, Primary Key
- name: String, Not Null, Indexed
- phone: String, Not Null, Indexed (NOT UNIQUE - families share phones)
- monthly_amount: Float, Not Null
- start_date: Date, Not Null
- duration_months: Integer, Not Null
- is_active: Boolean (default True) # Soft delete pattern
- created_at: DateTime (UTC)
- updated_at: DateTime (UTC, auto-update)
- Relationship: One-to-Many with Payment (cascade delete)
```

### 3. Payment (Monthly Installments)
```python
- id: Integer, Primary Key
- customer_id: Integer, ForeignKey(customers.id)
- due_date: Date, Not Null, Indexed
- amount: Float, Not Null
- is_paid: Boolean (default False)
- paid_date: Date, Nullable
- payment_month: Integer (1-12)
- payment_year: Integer (e.g., 2026)
- notes: String, Nullable
- created_at: DateTime (UTC)
- updated_at: DateTime (UTC, auto-update)
- Relationship: Many-to-One with Customer
```

## Key Business Logic

### Customer Creation Flow
1. Validate input (name, phone, amount, start_date, duration)
2. Create customer record
3. **Auto-generate monthly payment records** (duration_months count)
   - Due dates: 5th of each month
   - Amount: customer.monthly_amount
   - Status: unpaid (is_paid=False)
4. Return customer with generated payments

### Payment Marking Flow
1. Find payment by ID
2. Toggle is_paid status
3. If marking as paid: set paid_date to today
4. If reverting to unpaid: clear paid_date
5. Update updated_at timestamp

### Reminder Logic (Daily at 9 AM)
1. Query all unpaid payments where due_date <= today
2. Group by customer
3. For each customer with pending payments:
   - Check localStorage reminder tracking (frontend)
   - Send WhatsApp message via Twilio (if enabled)
   - Format: "Hi {name}, reminder for pending payment of ₹{amount}..."

### Dashboard Statistics
- Total customers (active only)
- Total amount collected (all paid payments)
- Pending payments count
- Month-wise collections (group by payment_month/payment_year)

## Coding Conventions

### Backend (Python)
1. **Use type hints** everywhere (PEP 484)
2. **Pydantic schemas** for all request/response validation
3. **SQLAlchemy ORM** - Never write raw SQL
4. **Dependency injection** for database sessions
5. **JWT authentication** on all routes except /login, /health
6. **UTC timestamps** - Use datetime.utcnow()
7. **Error handling** - Raise HTTPException with appropriate status codes
8. **Docstrings** - All functions need docstrings
9. **Async/await** - FastAPI endpoints are async when possible

### Frontend (JavaScript)
1. **No external libraries** - Pure vanilla JS
2. **State management** via JavaScript objects (currentUser, app state)
3. **localStorage** for token persistence
4. **Fetch API** with error handling
5. **Mobile-first** - Test on smartphone viewport
6. **Single responsibility** - One function = one task
7. **Screen-based navigation** - showScreen() function pattern
8. **Form validation** before API calls

### Database
1. **Never delete data** - Use soft delete (is_active flag)
2. **Cascade deletes** defined at model level
3. **Indexes** on frequently queried fields (phone, due_date, name)
4. **Timestamps** on all models (created_at, updated_at)
5. **Relationships** explicitly defined in models

## Common Implementation Patterns

### 1. Protected API Endpoint
```python

@router.get("/protected")
async def protected_route(current_user: User = Depends(get_current_user)):
    # current_user is automatically injected
    return {"user": current_user.username}
```

### 2. Database CRUD Operation
```python

@router.post("/customers")

    customer: CustomerCreate,

    current_user: User = Depends(get_current_user)
):
    return crud.create_customer(db, customer)
```

### 3. Frontend API Call with Auth
```javascript
async function fetchData(endpoint) {
    const token = localStorage.getItem('token');
    const response = await fetch(`/api${endpoint}`, {
        headers: {
            'Authorization': `Bearer ${token}`,
            'Content-Type': 'application/json'
        }
    });
    if (response.status === 401) {
        logout(); // Token expired
    }
    return response.json();
}
```

## Troubleshooting Common Issues

### "Database locked" error
- SQLite doesn't handle concurrent writes well
- Reduce connection pool size or use PostgreSQL for production

### WhatsApp messages not sending
- Check `ENABLE_WHATSAPP=true` in .env
- Verify Twilio credentials with `python check_twilio.py`
- Check Twilio sandbox approval for recipient numbers

### Token expired errors
- Token lifetime: 24 hours (configurable in config.py)
- Frontend auto-redirects to login on 401
- Generate new token by logging in again

### Frontend not loading
- Ensure static files are in `static/` folder
- Check FastAPI is mounting static files correctly
- Verify index.html exists

### Payments not auto-generating
- Check `crud.create_customer()` logic
- Verify `generate_payments()` function is called
- Duration must be >= 1
